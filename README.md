# dsh-creator-overlay

把 DSH Web 的「创造模式」从第四个预设拆出来，变成新会话输入卡上方的一个「创造」开关：

- 基础模式仍是标准、PTC、极简三种，选择方式不变。
- 开关打开时，会话在所选基础模式的完整组合上叠加创造增量（`tool-cordis` 的只读检查工具、创造技能目录、插件管理器与插件市场工具）。
- 开关只在新会话的第一轮之前可用；会话开始后宿主会拒绝切换，开关隐藏。
- 原生「创造模式」预设和它的两个创建入口（设置页、插件页）不再出现在界面上。

## 组合方式

DSH 的预设是一份扁平插件列表，一次会话只绑定一个预设，没有继承或按会话叠加。因此开关实际是在三个预设之间切换：

| 基础模式 | 开关关闭 | 开关打开 |
| --- | --- | --- |
| 标准 | `standard` | `cordis`（原生创造预设，本身等于标准 + 创造增量） |
| PTC | `ptc` | `ptc-creation` |
| 极简 | `minimal` | `minimal-creation` |

`cordis`、`ptc-creation`、`minimal-creation` 三个 id 会从客户端的预设名单里隐藏：模式选择器、设置页和原生创建入口都读同一份名单，所以隐藏后同时生效。会话日志仍按这些 id 记录，重启时由本插件在启动阶段重新注册组合预设。

`ptc-creation` 和 `minimal-creation` 的底座列表复制自 `@deepseek-ai/dsh-web-app` 的 `presets/ptc.patch.yml` 与 `presets/minimal.patch.yml`（见 `host/presets.js`）。DSH 升级后如果内置预设发生变化，需要重新同步这两份列表。

## 行为细节

- 打开开关会调用宿主的 `agentPresets/select`，只在空白会话上生效；已开始第一轮的会话不会出现开关。
- 开关打开时切换基础模式，会自动为新底座重新叠加创造组合，不会静默关闭。
- 启动时如果保存的默认预设仍是 `cordis`（或被隐藏的创造 id），会迁移为 `standard`，避免新会话默认进入创造模式。
- 组合预设通过包装预设注册表的 `remoteExportList` 从名单中隐藏。这是私有服务接口；包装失败时插件降级为「组合体可见」并在日志中说明，开关仍可使用。

## 已知限制

- 新会话的模式芯片在开关打开时会显示组合 id（如 `cordis`），因为该 id 已从名单隐藏；会话标题旁的标签会显示「标准模式 + 创造」这类映射文案。
- 完全没有会话的首屏（未选工作区）没有输入卡上方槽位，开关只在空白会话出现后显示。
- 卸载本插件后，记录为 `ptc-creation` / `minimal-creation` 的既有会话将无法恢复（宿主找不到预设定义）；`cordis` 会话不受影响。
- 复制的基础预设列表不会自动跟随 DSH 升级。

## 安装

作为一个 bundle 安装到当前 profile：

```text
plugin_manager install_bundle <本目录绝对路径>
```

安装会启用 bundle 并写入 profile 依赖；卸载时移除该 bundle 即可恢复原生创造模式与入口。

## 文件

| 文件 | 职责 |
| --- | --- |
| `index.js` | 宿主半：注册组合预设、隐藏名单、迁移默认值 |
| `host/presets.js` | 复制自内置 PTC / 极简预设的插件列表 |
| `client.js` | 浏览器半：输入卡上方的「创造」开关与会话标题标签 |
| `cordis.patch.yml` | bundle 插入的 Loader 行 |
